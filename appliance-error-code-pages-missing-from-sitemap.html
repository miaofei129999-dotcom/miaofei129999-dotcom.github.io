Twenty-Six Pages About Error Codes, None in the Sitemap

The URL was the only thing missing.

This site indexes appliance model numbers — roughly 3,700 machines across eight categories, with a page each for the manual, the specs, the parts list and the known problems.

The problems page is the one people arrive from search on. "Maytag MVWB965H problems" is a real query. So is "Maytag MVWB965H error code F5E2". We answer the first. The second one we answer too, on a page under /error-codes/ — except the directory above it returns 404 and nothing in the sitemap mentions it.

The census

Two sitemaps, 1,668 and 9,600 URLs, no overlap, 11,268 unique.

The sub-pages split into parts 2,042, manual 1,551, problems 1,551, specs 1,551, error-codes 2.

Three types at exactly 1,551 is a batch boundary, not a decision. Parts overshoots it by 491 models, which is what you see when one generator kept running after another stopped.

What's actually broken

26 code pages exist, 0 are declared. Maytag 13, Whirlpool 13, every one returning 200, every one about 450 words: what you will see, likely causes in order, safe checks, when to call a technician, which other models show it. Real pages. Invisible to a crawler reading the sitemap, and the index at /error-codes/ returns 404 — so trimming a deep URL to its parent dead-ends.

The content is already written under another name. /maytag/washing-machines/mhw6630h/problems/ has a ten-row fault-code table. /maytag/washing-machines/mhw6630h/error-codes/ is 404. Three Maytag washers carry codes; two got the URL.

45.4% of model pages have nothing under them. 1,699 dead ends out of 3,741. Room AC, freezers, range hoods and dehumidifiers get zero sub-pages entirely — 100 models. Refrigerators leave 1,059 of 2,013 without a child page.

How far off this could be

I have no Search Console here, so I can't claim those 26 pages are unindexed. Internal links exist; brand hubs pass them twice. The honest version is "not declared, and the index 404s."

I checked 26 of 1,551 problems pages, 1.7%. And I verified no code meaning against a service manual — the F5E2 page is specific and confident, which is also how a wrong page sounds.

Correction

My first pass at the table returned F6E2F6E3 as a single code and I logged it as a rendering defect. The cell is a link plus a subtitle div: F6E2 the code, F6E3 its alias. My tag stripper joined them with nothing between. The page was correct. I was not.

*Disclosure: this is our own site. The numbers come from crawling it on 19 November 2026. The 404 is at /error-codes/.*

A route, a sitemap line, one template applied to a third model. Small. Invisible. And the kind of thing that only surfaces when someone types a URL instead of clicking one.
