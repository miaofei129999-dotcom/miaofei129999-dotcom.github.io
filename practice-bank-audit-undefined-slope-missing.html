Three Articles About Undefined Slope, Zero Practice Questions

Audit note, 2026-11-15. Files under review: /assets/app.mjs and /assets/math.mjs, both served from this domain. Method: extract the live question array, run it through the site's own slope(), then test the grader against eight inputs. Result: ten questions, eight distinct answers, zero undefined-slope questions, and one thrown exception that explains the zero.

How we measured

The practice page's own HTML is thin — 6,923 bytes, 173 words — because the questions are rendered client-side from app.mjs. Any audit that counts the HTML text and stops there will conclude the page is empty. It is not empty. It is small, and it is unchangeable.

I pulled both files with curl, took the slope bank as-is, and imported math.mjs directly into a Node 22 ESM script. Ten pairs of coordinates in, ten results out: rise, run, slope as an exact fraction, slope as a decimal.

The grader test called the same expression the page calls — parse(input).eq(answer) — with eight strings. Errors were caught and recorded rather than allowed to abort the run.

One correction to the record: an earlier note of mine put this page at 173 words total and called it the thinnest page on the site. That was measuring the HTML, not the page. The page is a five-question set with a hint button and a score. The real finding is that the set is ten questions wide and cannot grow in the direction the articles point.

Three things this set gets wrong

Not one of the ten has the same x on both points.

That means the set never asks for an undefined slope. Zero out of ten.

Our blog has 43 articles. Three of them are specifically about it: "When is a slope considered undefined?", "Undefined slope vs zero slope", and "When is a slope undefined? Two equal x-values". Three articles, roughly 3,600 words of teaching, pointed at a practice page that structurally cannot ask the question.

Here is why, and this is the part that matters. Feed a vertical pair into the page's own function and it returns mode: 'vertical' with no m at all. The render line then builds the explanation string by hand:

Slope = (6) / (0) = undefined

And the answer check calls parse(input).eq(answer) where answer is undefined. That throws. Not "marks wrong" — throws. I ran it: Cannot read properties of undefined (reading 'n').

So the practice cannot ask a question it cannot grade, and the grader was never taught the one case the articles promise. The bank is not missing a hard question by accident. It is missing the question that would crash.

Two of the ten have the same answer as each other, twice over.

Answer 0 appears at question 3 and question 8. Answer 2 appears at question 4 and question 9. Both pairs are different points on different lines, so they are not literally duplicates. But with eight distinct answers across ten questions, a student who guesses "0 or 2" covers 40% of the set.

And the set cycles between exactly two versions. The restart handler does set = (set + 1) % 2. Ten questions, two sets of five, then back to the start. Anyone who practises twice has seen everything, forever.

The public JavaScript ships our build notes in Chinese.

app.mjs: 589 lines, 90 of them contain Chinese characters, 82 of those are comments. math.mjs: 265 lines, 61 with Chinese, 54 comments. That is 151 comment lines going out to every visitor of an English-language site.

One of them, dated 2026-11-10, explains a bug we hit in production:

判断「这页有练习题」不能只看 #practice —— 文章正文里的 <h2 id="practice"> 会命中同一个 selector…

Roughly: don't detect "this page has practice questions" by looking for #practice, because a heading in an article body matches the same selector and then the code crashes on a null form. Someone spent an evening on that. It is now public, in Chinese, on a site for American students.

The site is English. Our notes are not. We minify the CSS and version it with a hash, and then ship the reasoning behind every function in a language our readers do not read.

One thing I wrote wrong this morning

Before I opened app.mjs, I wrote in our own notes that the practice page had 173 words and was the thinnest page on the site.

173 is what the HTML ships before the module runs. The page a reader actually sees has five questions, a hint button, a show-answer button and a score. The page is not thin. It has ten questions in total and cannot say so out loud. That is worse than thin, and I only found it because the first number I wrote down was wrong.

What this does not tell you

Whether ten questions is too few.

I have no completion data. The page fires an analytics event when someone asks for a hint and when someone gets one wrong. It does not fire anything when someone finishes, and it does not record whether a restart was a second attempt or a fifth. So I can count the bank and I can count the articles. I cannot tell you whether anyone is bored by question five, because we never measured that.

I also tested eight input formats for one answer. That is not proof that the grader accepts every reasonable way to type a slope. It is proof that it accepts eight of them, including 2/4 for 1/2 and .5 for 0.5.

Disclosure

I maintain Slope Calculator, the site whose practice set this is. The audit is of my own code, and the uncomfortable parts are the reason I published it.

Three articles about undefined slope, and the practice set will not touch it. Fixing that means teaching the grader what "undefined" is, which means changing the answer type, which means the next version of this page is not a content fix.

The order is: change the answer type so undefined is a legal answer, then add the two vertical questions, then rewrite the opening paragraph of three articles that currently end by sending readers to a practice page which cannot test what they just read.
